# StreamDrop Desktop

**Ваш помощник для перемещения файлов между интернетом и облаками** — без записи на диск и без лишних серверов.

**Скачать:** [StreamDrop v1.0.0 — Windows x64](https://github.com/Fellmonkey/StreamDrop/releases/latest) (один портативный exe, без установщика)

Поток идёт `HTTP → ОЗУ → rclone rcat`: крупные файлы попадают из Сети прямо в облачное хранилище, минуя накопитель. Интерфейс открывается в браузере на `127.0.0.1`; закрытие вкладки не прерывает передачу — сервис живёт в трее.

> English version: [`README.md`](README.md)

## Для кого и для чего

Это **личный инструмент**, а не enterprise-платформа: ваши файлы, ваша домашняя сеть, ваш компьютер. StreamDrop решает одну задачу — «перенести файл туда, где он нужен, не занимая диск и не возясь с промежуточными шагами».

Классический сценарий выглядит так: скачал на диск → подождал → залил в облако. StreamDrop делает это **в один приём**:

- файл идёт через ОЗУ — **накопитель не изнашивается** и не переполняется;
- **не нужен свободный объём** под временный файл, даже для много гигабайтного ISO;
- параллелизм и очередь делают передачу **пачками** удобной — не только для больших файлов, но и когда файлов много;
- всё контролируется из одного окна, статус и скорость видны и в трее.

Честные оговорки:

- Скорость всё равно ограничена вашим интернет-каналом и провайдером облака.
- Экономия времени ощутима там, где диск медленнее канала; с быстрым NVMe выгода — в первую очередь в износе и удобстве.
- Это не универсальный «качалка»: поддерживаются прямые ссылки на файлы, HTML-страницы (через yt-dlp) и ограниченный набор протоколов.

**Идея шире, чем «скачать в облако».** Фундамент проекта — rclone, который от рождения умеет переносить данные между любыми парами хранилищ: облако → облако, локальный диск → облако и так далее. StreamDrop открывает этот потенциал постепенно: сегодня доступен сценарий интернет → облако; следующие шаги — источники «другое облако» и «локальная папка», чтобы переносить файлы, не делая ПК промежуточным звеном (см. роадмап).

## Возможности

- Предполётная инспекция: редиректы, HEAD → Range-GET, имя/размер/тип, детекция HTML.
- Два режима: `ring_buffer` (32–1024 MiB) и `pure_stream`; движки `curl` / `yt-dlp` / встроенный.
- Очередь: параллелизм 1–5, ручной порядок, пауза, retry, докачка по `Range`, SHA-256 на лету.
- Облака: Mail.ru (WebDAV), Яндекс.Диск, Google Drive, OneDrive, S3, WebDAV, FTP, SFTP; проводник, квоты, создание папок. OAuth — на `127.0.0.1:35357`.
- Профили авторизации источника: cookies браузеров (Windows), импорт `cookies.txt`, User-Agent/Referer.
- Компоненты (rclone / yt-dlp / curl) ставятся автоматически с проверкой SHA-256.
- Уведомления: toast + Telegram.
- Самообновление с GitHub Releases.
- Метрика «Сбережено»: байты, не записанные на диск; время, которое занял бы дисковый цикл; ресурс перезаписи.
- Локализация ru/en.

## Быстрый старт (Windows)

```bash
make build-windows            # web/dist + bin/streamdrop.exe
./bin/streamdrop.exe          # откроет http://127.0.0.1:8085
```

Если порт занят — берётся следующий свободный; адрес в логе. Компоненты скачаются при первом запуске.

## Сборка

Требования: Go 1.27, Node.js 22+, npm.

```bash
cd web && npm ci && npm run build && cd ..
go build -trimpath -ldflags "-s -w -H=windowsgui" -o bin/streamdrop.exe ./cmd/streamdrop
```

Фронтенд собирается до `go build` (`web/embed.go`). Иконка — `cmd/streamdrop/rsrc_windows_amd64.syso`.

## Конфигурация

| Флаг | По умолчанию | Назначение |
| :--- | :--- | :--- |
| `--port` | `8085` | порт UI |
| `--host` | `127.0.0.1` | только loopback |
| `--data-dir` | `%LOCALAPPDATA%\StreamDrop` | БД, логи, компоненты |
| `--no-tray` | выкл. | без иконки в трее |
| `--no-browser` | выкл. | не открывать браузер |
| `--update-repo` | `Fellmonkey/StreamDrop` | GitHub owner/repo |

Данные: `streamdrop.db`, `logs\`, `deps\`, `crash\`, `update\staging\`. Демон также пишет `run\daemon.json` (порт, одноразовый токен, pid) — файл обнаружения для внешних клиентов; удаляется при завершении.

## ИИ-интеграция (MCP)

Сам `streamdrop.exe` может выступать MCP-сервером для агентов (Claude Desktop, OpenCode, Cursor) через stdio — без дополнительных скачиваний и второго бинарника. Он открывает 15 типизированных инструментов (статус, облака, задачи, очередь, компоненты, обновления). Порт и токен читаются из `run\daemon.json` при каждом вызове — рестарт демона не требует перенастройки.

Настройте MCP-клиент на запуск:

```
C:\Users\<вы>\Downloads\StreamDrop\streamdrop.exe mcp
```

Примеры конфигов клиентов (замените `<вы>` и путь): `examples/mcp-claude.json`, `examples/mcp-opencode.json`. Если каталог данных нестандартный — добавьте `--data-dir <путь>` к аргументам.

- Инструменты возвращают машинные коды ошибок (`source_unreachable`, `daemon_unreachable`, `validation_failed`, ...); для работы любого инструмента демон должен быть запущен.
- MCP опционален: если вы не пользуетесь ИИ-агентами, просто игнорируйте подкоманду `mcp`. MCP-серверы никогда не запускаются сами — только по команде клиента MCP.

## Безопасность

Только `127.0.0.1`; REST защищён одноразовым токеном и проверкой Origin/Host; секреты шифруются (DPAPI / AES-256-GCM); телеметрии нет; API не отдаёт секреты ни в логах, ни в ответах.

## Ограничения (честно)

- **Эталон — Windows 10/11 x64**; macOS/Linux собираются, но не являются эталонными релизами.
- **Google Drive / OneDrive** требуют собственного OAuth-приложения (инструкции — в мастере); **Яндекс.Диск** — флоу с verification code.
- Chromium 127+ (App-Bound Encryption) не позволяет читать cookies стороннему процессу — используйте `cookies.txt`.
- Нет докачки после смерти процесса и рекурсивного поиска по всему облаку.
- Обновления проверяются по SHA-256; подпись — при настроенном ключе.

## Роадмап

Приоритеты, без обещаний по срокам:

1. **Полная поддержка Linux/macOS** — эталонные сборки, установщики, автообновление.
2. **Источники: другое облако и локальная папка** — облако → облако, диск → облако и обратно. Механика уже есть в rclone (remote-to-remote); нужна обвязка источников в интерфейсе.
3. **Torrent / magnet-источники** — стриминг без полного скачивания.
4. **Telegram** — управление очередью из чата, события по файлам, статус по запросу.
5. **Расписания (cron)** — «забрать релиз по пятницам».
6. **WebDAV-сервер как назначение** — приём файлов из других инструментов.
7. **Рекурсивный поиск и фильтры** по облаку.
8. **Прокси/VPN-режимы** для источников.

Сознательно не планируется: телеметрия, браузерные push, мобильные клиенты.
